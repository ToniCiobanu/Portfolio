Getting my work shifts into Google Calendar automatically

My employer's scheduling system (Synerion) can export a month of shifts but can't sync to a calendar, so I was retyping every shift by hand. This is the small pipeline I built to replace that: a spreadsheet that parses the export, and a script that creates the events.

ProblemPipelineParsing ScriptTestsLimits

The problem

The export puts the date and both times in one text cell:

3/31 - 13:00-21:15

Google Calendar needs a real start and end date-time for each event. Typing a month of shifts in by hand was slow, and a typo meant a shift that conflicted with classes or plans without my noticing.

The pipeline

Step 1

Export

Download the month's schedule from Synerion as CSV and paste it into the sheet.

Step 2

Parse (Sheets formulas)

Split the text into a start and end date-time in columns A and B.

Step 3

Sync (Apps Script)

Create a calendar event per row with a 60-minute reminder, then mark the row "Added" so re-running it never makes duplicates.

The sync script

        
The script is bound to the spreadsheet and runs from the Apps Script editor. The design choices worth calling out:

        
    
            
  • Safe to re-run. Each synced row gets "Added" written to column C and is skipped next time, so running it twice can't double-book.
    • 
            
  • Bad rows are skipped, not fatal. Blank rows, formula errors (which arrive as strings, not Dates), and rows where the end isn't after the start are skipped and counted.
    • 
            
  • One failure doesn't stop the batch. Each event is created inside its own try/catch; a failed row stays unmarked, so the next run retries it.
    • 
            
  • It reports what it did. It logs and returns added / skipped / failed counts.
    • 
        

        

    






    

        
Tests

        
Apps Script normally only runs inside Google. The tests replace SpreadsheetApp and CalendarApp with small fakes so the same Code.gs file runs under Node. They cover re-runs, bad rows, and an API failure mid-batch. Run them with:

        
node --test projects/calendar-sync/test/*.test.js

        

            
            
        

        

    






    

        
Limits, and what I'd change

        
    
            
  • Changed shifts aren't updated. The "Added" flag only records that a row was synced. If a manager moves a shift, the old event stays. The fix is to store each event's ID in the sheet so the script can update or delete it.
    • 
            
  • Time zone comes from the script settings. Fine for one person in one time zone; it would need to be explicit for anyone else.
    • 
            
  • Still one manual step. I export and paste the CSV myself each month. Synerion has no API I can use, so this is where the automation stops.
    • 
            
  • Scale. This is a personal tool handling one person's monthly schedule, not a production integration.
